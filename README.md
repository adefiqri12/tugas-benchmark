# indo-eval

An evaluation harness for **AI agents that call tools, in Bahasa Indonesia**.

Most Indonesian-language benchmarks (SEA-HELM, IndoNLU, IndoMMLU, Cendol) measure
*understanding* (NLU). Almost nothing measures whether an agent **picks the right
tool, with the right arguments, in the right order** when the user speaks
Indonesian. This project measures exactly that — and publishes a public leaderboard.

## What it measures

Given an Indonesian prompt, a correct agent must produce a specific tool-call
trace. The harness scores the trajectory, not just the final text:

| Metric | Question it answers |
|---|---|
| `exact_match` | Was the whole expected trace reproduced, in order? |
| `tool_selection` | Of the tools that should fire, how many fired at all? |
| `arg_accuracy` | Of the expected arguments, how many matched? |
| `steps` | How many tool calls did the agent actually make? |

Every failure is labelled with a cause: `NO_TOOL_CALL`, `WRONG_TOOL`,
`MISSING_TOOL`, `BAD_ARGS`, `EXTRA_TOOL`, `ORDER_ERROR`, `API_ERROR`.

## Quickstart

```bash
uv venv && uv pip install -e ".[dev]"
indoeval list                      # show the golden tasks
indoeval run -m auto/best-fast     # score a model
pytest -q                          # scorer tests (offline)
```

The runner talks to any [OI]-compatible chat endpoint that supports tool calling.
Point it at your gateway with `INDOEVAL_BASE_URL` / `INDOEVAL_API_KEY`
(default: `http://127.0.0.1:20129/v1`).

## Layout

```
src/indoeval/
  models.py   Task, ExpectedCall, Trajectory, TaskResult, FailureType
  tools.py    mock Indonesian tools (parse_tanggal, cari_penerbangan, cek_cuaca, hitung)
  agent.py    LLMAgent (gateway) + ScriptedAgent (offline baseline)
  score.py    trajectory scoring + failure taxonomy
  runner.py   load tasks, run an agent
  cli.py      indoeval list | run
eval/datasets/golden_id.json    seed tasks
tests/                          offline scorer tests
```

## Status

Phase 1 (scaffold + first numbers). The harness runs end-to-end and prints a score
table. Next: grow the task set to 30-50, add an LLM-judge for the final answer,
deploy a public leaderboard.

## Design note

Tools are deterministic and offline so a run is reproducible — the score measures
the *agent*, not an upstream API. Ground truth is hand-written, never generated by
a model: a judge-produced "correct" trace measures agreement with the judge, not
agent quality.
